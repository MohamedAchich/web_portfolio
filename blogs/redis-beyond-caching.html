Redis beyond caching: leaderboards, locks, and rate limits

Ask most engineers what Redis is for and they'll say "caching." That's true, and it's also the least interesting part of what it does well. The data structures Redis ships — sorted sets, hashes, streams — solve real problems that would otherwise mean standing up a purpose-built service.

Leaderboards are a sorted set, not a query

A naive leaderboard is "SELECT ... ORDER BY score DESC LIMIT 100" against your primary database, re-run on every page load. That's fine at low traffic and falls over the moment ranking becomes a hot path. A Redis sorted set gives you O(log N) inserts and O(log N + M) range reads, with rank lookups included for free:

ZADD season:leaderboard 4210 "player:8841"
ZREVRANK season:leaderboard "player:8841"
ZREVRANGE season:leaderboard 0 99 WITHSCORES

The trick that matters in production: treat the sorted set as a rebuildable projection, not a source of truth. Keep the authoritative score in Postgres, and rebuild the Redis structure from it on deploy or on demand. That way a Redis flush is an inconvenience, not data loss.

Distributed locks, carefully

SET key value NX PX 30000 gives you a lock with an expiry in one atomic command — useful for making sure only one worker processes a given job. The caveat that trips people up: a lock with a timeout is not a correctness guarantee if the operation can outlive the timeout. If you need real fencing, pair the lock with a monotonically increasing token and have downstream writes check it, rather than trusting "I hold the lock" alone.

Rate limiting without a database round trip

A sliding-window rate limiter fits in a handful of Redis commands wrapped in a Lua script for atomicity — no separate service, no extra network hop to a database. For anything device-facing, where you might have thousands of clients checking in on a schedule, that atomicity is what keeps the limiter itself from becoming the bottleneck it was supposed to prevent.

None of this replaces Postgres. It replaces the instinct to reach for a general-purpose database for a problem that has a purpose-built data structure sitting one dependency away.
